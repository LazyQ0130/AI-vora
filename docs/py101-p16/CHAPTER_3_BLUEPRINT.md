## 3.1 让程序根据条件决定是否执行

问题：已有True/False，为什么后面的提示还总显示？先修：1.3保存完整运行、2.1赋值、2.2 bool、2.4单比较；已学2.5/2.6可复用但核心不强求。首次语法：if关键字、条件后冒号、多行缩进块、缩进结束后的继续执行。

目标：①独立写简单if并解释真路径；②区分块内外，正确冒号/缩进并预测假路径；③固定规则和上限，用低/等/高新值预测并实际运行，解释等值。主例：

```python
count = 5
limit = 6

if count <= limit:
    print("Within limit")

print("Check finished")
```

先预测5的两行；只改7后应仅Check finished；再改6应两行。误以为假时全停，用块外print最小重跑；误以为冒号下面全部受控，只移动一条print缩进对照。独立成果：自选新容量/库存/达标情境的新.py，指定提醒受if控制，结束提示在块外。

核心题方向：choose-when-to-print自定名称/规则/数据并三轮；repair-if-block修复可运行的单一逻辑缩进错，留修前/后真、假路径。两级提示先找受控提醒再检查归属，不交完整答案。暂缓else/elif/逻辑组合/循环/嵌套/容器；下一节解决条件不满足时另一种动作。时间见总表，缩进首次操作负担待试学；项目意义是让判断开始影响实际动作。

## 3.2 条件不满足时怎么办

问题：满足与不满足需要各显示一种提示，怎样确保只选一条路？先修：3.1真假路径、块归属与边界，第二章数值比较。首次语法：else及其冒号/同层对齐，随后elif的条件；按顺序只执行首个真分支，else作余下情况。

目标：①用if/else实现两种互斥动作；②从低/等/高三类规则写出if/elif/else并预测唯一分支；③用边界实跑，解释多条独立if与一条选择链的区别。先两路后累计到主例：

```python
count = 6
limit = 6
if count < limit:
    print("Room left")
elif count == limit:
    print("At limit")
else:
    print("Over limit")
print("Check finished")
```

预期At limit、Check finished；5/7各为Room left/Over limit加结束。诊断：若预测多提示，沿首个成立分支逐项走；在副本用重叠条件对比两个独立if与选择链。独立成果：新三档数量提示脚本。

核心题方向：choose-one-message新阈值三档实跑；repair-overlapping-choice给出能重复提示的独立if，先观察再用互斥链修复。延后逻辑运算/嵌套/循环/异常；下一节让一个分支同时看几条规则。时间见总表，先两路后多路的分量待教师复核；项目意义为每项检查给出明确分类，避免互相矛盾的处理。

## 3.3 多个条件怎样共同决定结果

问题：数量既要够用又不能超库存，怎样写成一个可核对的条件？先修：3.1–3.2与单比较；不依赖任意对象真值。首次语法：and/or/not，括号明确组合；先分开求比较，再解释连接规则，只用bool操作数。

目标：①把“同时/至少一项/取反”写成组合；②为一个条件列出能区分各项的测试数据；③从错误放行结果定位and/or的混淆。主例：

```python
count = 5
minimum = 3
stock = 6
if (count >= minimum) and (count <= stock):
    print("Quantity ready")
print("Check finished")
```

预期两行；2/7均仅结束；边界3/6均通过。先口头分别判断左右，再核对组合；把and误作or时只改为2观察错误放行。or用“任一项需补查”，not先对一个完整比较取反，解释求值到结果已确定时可跳过右项，不把有副作用的操作藏入条件。

独立成果：新材料数量范围或两项bool规则脚本。核心题方向：combine-quantity-rules新上下界、至少四组区别数据；diagnose-connector只错一个连接词，学生提出最小反例并修复。延后链式比较、位运算、容器真值和复杂优先级表；下一节复用条件但让状态变化。时间见总表，not与中文否定易混需试学；项目意义是明确记录筛选标准与测试边界。

## 3.4 让程序重复执行直到条件变化

问题：还没数到目标时，怎样自动再做一次？先修：3.1条件块、2.1重新赋值、2.3加法；3.3可读简单组合但主例只一个比较。首次语法：while、每轮重查条件、循环体和状态更新。

目标：①按初值/条件/更新写出有限while；②追踪每轮值与最后退出值；③预测零轮和恰到边界，修复漏更新的逻辑。主例：

```python
packed = 0
target = 3
while packed < target:
    packed = packed + 1
    print(packed)
print("Packing finished")
```

预期1、2、3、Packing finished；初值3时零轮、只有结束。先预测第三轮后条件，避免把while理解成只检查一次。漏更新例先纸面追踪，不启动无穷循环；需要中止的工具操作在正式简报核验，不用故障实验冒充目标。

独立成果：自定起始量/目标的有限任务计数。核心题方向：count-to-target新目标并验证零/多轮；repair-state-update给出单一更新位置/方向错误，学生先指出停止条件再实际跑修复稿。延后break/continue、while-else、函数/容器；下一节比较事先知道次数的重复。时间见总表，状态追踪最不确定；项目意义为逐步推进处理状态并能证明停止。

## 3.5 已知重复次数时怎样写循环

问题：已知要核对三批材料，还需自己更新计数器吗？先修：3.4循环体、执行轮次和状态概念。首次语法：for 名称 in range、range(stop)及range(start, stop)，结束值不取；不将range说成已创建的列表。

目标：①写固定次数for；②解释每轮名称取得的整数及结束边界；③结合已学if预测每轮与块外动作。主例：

```python
for batch in range(1, 4):
    print(f"Batch: {batch}")
print("Check finished")
```

预期Batch: 1/2/3后结束。先预测有没有4，再只改stop为5重跑；range(0)零轮只结束。独立成果：新批次数的编号核对脚本，亲自决定范围。

核心题方向：check-fixed-batches按新编号需求写循环；repair-range-endpoint给单一差一错误，学生用边界定位并修复。延后列表、步长/负步长全集、enumerate及循环else；下一节控制一轮与整个循环的去留。时间见总表，0起点和不含结束值待试学；项目意义为逐条/批执行并减少手工重复。

## 3.6 怎样提前结束或跳过一次循环

问题：一批不处理，和全部停止有何差别？先修：3.1 if、3.4/3.5循环执行顺序。首次语法：continue跳到下一轮、break结束当前最内层循环；以单层for降低更新遗漏风险。

目标：①区别两种跳转目的；②追踪跳转后本轮余下语句、下一轮和块外语句；③用新编号实跑修复错用的控制语句。主例：

```python
for batch in range(1, 5):
    if batch == 2:
        continue
    if batch == 4:
        break
    print(batch)
print("Check finished")
```

预期1、3、Check finished。先分别教只含continue和只含break的短版，主例才组合；误认continue全停，用编号3验证；误认break停程序，用块外结束验证。简短纸面核对while中continue可能绕过更新，不必真跑无穷循环。

独立成果：自选跳过号和停止号的批次脚本。核心题方向：skip-one-stop-later新范围两种跳转；repair-jump-purpose只错一个跳转词，先预测故障再修复。延后循环else、多层跳出、异常、函数返回；下一节将动作落实到实际数量输入。时间见总表，跳转位置是风险点；项目意义为记录跳过/停止的理由且保留收尾步骤。

## 3.7 组合条件和循环完成小任务

问题：怎样连续检查几批材料，并统计合格数量？先修：2.5合法整数输入/转换、2.6摘要、3.1–3.6，特别是累加前的赋值与continue。首次语法：无新关键字；把循环内分支形成必要的简单嵌套，正式解释哪些语句每轮执行、哪些只在通过时执行。主例：

```python
accepted = 0
total = 0
for batch in range(1, 4):
    count_text = input("Count: ")
    count = int(count_text)
    if (count < 0) or (count > 6):
        print("Skip batch")
        continue
    accepted = accepted + 1
    total = total + count
print(f"Accepted: {accepted}")
print(f"Total pieces: {total}")
```

输入2/9/4，print结果Skip batch、Accepted: 2、Total pieces: 6；三次input提示与键盘回显另记。先预测第三批是否仍被检查；若错误批也累计，逐行找continue和累加位置。输入合同为整数文本，0合格但不增加总件数，非数字异常留第八章。

独立成果：新限额/批次数的命令行检查与统计小脚本。核心题方向：batch-check-summary独立组合并含全部合格/部分跳过；repair-accumulation给一处累计位置错误，保留修前后新输入结果。延后函数化、列表存储、CSV、Pandas、文件和自动输入校验；下一节提出“想保留每批变换结果”的需求。时间见总表，整合和输入记录负担待试学；项目意义为筛选、计数、求总量的可复现基础，但尚非结课清洗工具。

## 3.8 从重复操作认识推导式

问题：重复算出的每批用量，怎样保存为一组新结果？先修：3.5 for与3.7任务经验；**列表不是已经学过的先修**，本节必须先完成最小桥接（见先修决定），桥接属于核心且在推导式之前。

首次语法：简单列表字面量`[]`与逗号、整体print/按顺序for读取；随后单层列表推导式。目标：①独立创建新整数列表并逐项读取；②将已解释的逐项数值变换写为简单推导式，说明得到新列表；③对新数据逐项手算/实跑核对并指出原列表保持。累计主例：

```python
counts = [2, 4, 6]
print(counts)
for count in counts:
    print(count * 2)
needed = [count * 2 for count in counts]
print(needed)
print(counts)
```

预期[2, 4, 6]、2×/4×/6×分别为4/8/12三行、[4, 8, 12]、原[2, 4, 6]。主例前分段讲，不能先整段让未学列表的人猜。先预测`needed`整体是否会是三个独立print，再运行区分“逐项显示”和“建立新列表”。原列表末次显示核对未修改。

独立成果：本人新三项数量列表、已学算术变换所得新列表及逐项对照。核心题方向：build-and-transform先过独立列表桥接再自选每份用量变换；diagnose-display-or-collection给误将逐项print当保存结果的短程序，让学生解释并建立可观察新列表。延后索引/切片/修改/append、筛选子句、嵌套、字典/集合/生成器推导式，第四章系统展开。时间见总表，桥接最不确定；项目意义为把多条变换结果交给后续容器操作，仍不要求读取文件。
