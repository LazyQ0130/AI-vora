# 3.2 开写前教学简报

身份：PY101 / PY101-C03 / PY101-C03-L02，《条件不满足时怎么办》，order2、r1、非可选。L1读者刚完成3.1首次if，尚未学else/elif、逻辑组合、循环、容器或函数定义。

核心问题：一个条件不满足时怎样执行另一种动作；有三种数量情况时怎样只给出一个对应分类？贯穿活动材料数量检查。5/6/7件与固定6件上限均为原创教学构造，条件只用已经会的整数比较。

真实先修由PREREQUISITE_AUDIT逐条resolve并核版本/锚点：1.3/r2保存与重跑；2.4/r2单比较/边界；2.6/r2可读摘要按序已学但核心不强求输入或f-string；3.1/r1的first-if、block-boundary与change-and-boundary提供if、冒号、四空格、块外继续和三值实跑。不是用旧r1第二章替代当前先修。

新语法首次位置：two-ways先用自然语言解释else、else:无独立条件、与if对齐、两个块各4空格，说明正常情况下只选一块，再展示完整两路代码；three-ways先提出少/等/超需求并解释elif的条件、冒号和顺序，再贴三档完整主例。不能以完整多分支语法表开场。

讲解顺序：3.1单if回顾→count7只有结束、需要另一个动作→else与两路→5/7先预测保存实跑→6归<=真路→三种分类需求→解释elif→三档完整主例与5/6/7分别运行→重叠<=抢先命中等值→只改<复跑→两个独立if同时提示→独立两题→折叠参考与下一组合条件问题。八个教学环节按需要形成标题，不凑数量。

主例两路：count5、limit6，<=控制Within limit，else控制Over limit，块外Check finished。三路：count6，第一项<显示Room left、第二项==显示At limit、余下Over limit，再结束。完整独立预解见PRE_SOLUTIONS，预期先于进程保存，实际退出0仍需对照分类规则。

题一choose-one-message：自定新数量情境、名称、新限制和提示；先完成if/else并真/假实跑，再改成三档并低/等/高三轮。源码一份加阶段差异，两个阶段必要预测/真输出和一条解释；不重复环境卡。参考改用座位14个、人数11/14/17。题二repair-overlapping-choice：套件10/上限10，两个独立if会给Within shelf limit与At shelf limit；任务明确只要少/等/超的一种分类。学生先实跑重复，再自行改结构和必要比较，三值8/10/13验证。只换elif但保留<=会遮住等值，修复必须解释范围，而非删print凑输出。

两级提示：先辨自然规则/有几个独立判断，再看同层对齐、比较范围和顺序；不交最终源码/变量/答案。答案解释每阶段原因、常错和等价合理写法，rubric检验真实操作而非看过答案。

典型误解A“所有真elif都会执行”：等值时第一<=已真，后面的==未实际检查；只改首项<核对At limit。误解B“两个if天然互斥”：保持相等，对照独立判断的两行与链的一行。正文用输出/逐行说明，作者可另用标准库trace观察实际执行行；trace不是学生先修或教学代码。

边界：只简单比较和顶层选择链；无and/or/not、循环/range、嵌套、match、条件表达式、容器、def、异常捕获、输入重试。else用于条件假路径，一次正常运行不会自动重试或捕获Python错误。无新图/下载，代码对齐和短表直接表现选择。

分项编辑估计沿P16：阅读12–18、练习8–12、代码20–30分钟，共40–60，basis=editorial-estimate；三类不重计，安装/故障另计。两路先独立闭环再增加等值，需教师/真实试学核对else+elif是否过载；未以字数或自动通过证明时长/效果。教师、中文教学编辑、目标学生、macOS实机均待办，不填reviewEvidence。
