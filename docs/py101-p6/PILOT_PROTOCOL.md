# 零基础学生试学组织方案（尚未开展）

本方案针对六节现行r1及P6材料。它是人工组织说明，不是第七节教材、网页系统或学习成绩。Codex只做技术预检，不算参与学生。实际开试前由组织者填写本次课程提交SHA、教师/编辑处理意见和样例指纹；若后续修订，按实际稿重新绑定证据。

## 准备和分工

- 专业教师先使用 [教师包](TEACHER_REVIEW_PACK.md) 决定哪些问题须修后再试；中文编辑使用 [编辑包](EDITORIAL_REVIEW_PACK.md)。尤其明确P6-02自选名称的处理，不能悄悄补讲后称无帮助完成。
- 组织者安排自愿参与的目标学习者：会开软件、创建文件夹、保存文本；进入1.1前不要求Python经验。按实际招募记录编程经历，不混入熟练开发者后宣称零基础学习效果。
- 建议先做小规模形成性观察，优先分别安排Windows与macOS；数量按实际条件填写，不预设通过率或用小样本推断总体。macOS必须在真实设备上预检后才开展其操作分支，当前仅有文档核对。
- 学习者只拿现行六节正文及 [学生任务纸](PILOT_STUDENT_TASKS.md)、[学生样例目录](pilot-student/)。组织者保管 [故障卡、分级提示与核对要点](PILOT_ORGANIZER_KEY.md)，不要把整个P6目录发给学习者，目录含答案和作者技术结果。
- 技术支持只处理获准安装、权限、网络或设备故障；任何概念补讲、命令纠正均记入帮助。不要更改系统安全策略、全局PATH、旧项目或现有学习进度。

## 阶段A：按1.1–1.6顺序学习

1. 按实际可读页面依次学习，阶段A结束于1.6。技术“下一节”可能去第5章，组织者不将它当作后续零基础课程。
2. 先无提示做每节两道核心题，保存预测及首次真实尝试。自查Quiz、网页读完不作达标证据。需要时学习者自行展开提示1，再提示2；看参考答案、回看正文、教师帮助均如实记下。
3. 不为了实验强迫受阻者无期限等待。出现挫折、安装失败或权限问题可暂停；记录首次卡点和未完成部分，技术支持完成后另记后续表现。观察者不代键入答案或替换源码后算其完成。
4. 每节结束收必要.py/.ipynb、短记录及实际命令/结果；下节按先修需要核对是否能继续。有教师补讲可继续形成性观察，但之后表现不能混入无人补讲的独立结果。
5. 六节可分多次完成，按学生意愿安排休息/结束，不把229–343分钟编辑估计变成限时考核。该总数不含安装/异常，不是试学数据。

## 阶段B：独立迁移（三个紧密相关小任务）

在完成六节之后使用学生任务纸，案例为包裹提示，不复制正文的主例标记。新位置中的pilot-box为目标项目、neighbor仅作可辨认的另一环境。三个任务共享一份短记录，分别处理保存运行、环境错配、Notebook状态；不把所有故障叠加成一个长项目。

准备和分级提示严格按组织者核对要点执行。B阶段不要求外部网络服务、模型API或临时复杂依赖安装；Notebook在测量前准备好。首次需要联网安装的时段单列，不算Python能力失败。若技术支持代建了目标环境，标明“环境创建未独立验证”，不覆盖任务一创建能力的缺口。

学生先尝试，可回看六节正文（记录回看位置），但不看参考答案/组织者页，不用AI给答案。观察者只说“按题纸记录你实际看到的情况”，不提前给最后修复命令。请求帮助时按提示1→提示2→教师补讲逐级提供。开始/暂停/终止由实际参与者决定，不按作者运行秒数设限。

阶段B结束后，可征得同意安排另一位真人仅凭脱敏文件与短记录尝试重做。接手者需按自己位置重建环境；记录接手者是否需额外提问、哪个条件缺失。未有人重做时写“他人复现待验证”，同机新Shell不替代这个证据。
