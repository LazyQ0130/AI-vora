> 日期：2026-10-26  
> 适用平台：Aivora（独立的系统性 AI 技术学习平台）  
> 教学载体：**图文、数学公式、图示、代码、练习与下载式实验**；不依赖视频或运行时 AI 助手  
> 配套文件：仓库 `curriculum/`（课程体系事实）、`docs/COURSE_AUTHORING.md`（工程接入与发布规则）

## 0. 一句话原则

**把初次接触这门知识的人教会，而不是把这门知识解释一遍。**

写作者应当像一个真正理解知识、熟悉学生困惑的教师：先发现学生已有认知与待解决的问题，再选择合适的解释、数字、图示、代码和练习。课程不以长度、术语数量、配图数量或结构模板完整度衡量质量。

优先级：**事实准确 > 学生能理解 > 学生能完成独立任务 > 表达自然 > 视觉形式与动效**。专业深度不能通过堆砌超纲术语实现；通俗也不能通过牺牲定义准确性获得。

## 1. 适用范围与角色

- **课程体系**：按 `curriculum/` 中稳定的课程、章节、先修与学习目标组织；新增节级课时须与章级事实一致。
- **课程目录**：第 n 章 → n.m 节，每节是可独立打开的完整教学文章；课程目录保留 `2.1`、`2.2` 等显示编号。
- **正文**：H1 使用课时自然标题；H2 为主要教学环节；有真实下级内容才用 H3。**不在正文标题和文章目录显示 2.1.1、01 等重复数字**。保留稳定的标题锚点、右侧文章目录和移动端导航。
- **进阶内容**：核心必学 / 可选进阶 / 可选代码验证分层。核心达标不依赖可选区内容，练习和目标应同时对应。
- **生产方式**：AI 可以参与检索、提纲、起草、插图实现、代码、初审，但不得自行充当独立的事实来源、专业审核者或真实试学者。
- **与工程规范关系**：本文件规范“讲什么、怎么讲、怎样审”；`docs/COURSE_AUTHORING.md` 规范模型、组件、路由、下载、技术测试、发布。发生冲突时分别处理教学目标与技术可行性，不能默默舍弃其中任意一项。

## 2. 先规划课程中的学习过程，再写文章

每节开写前必须形成一份**编辑简报**，至少包含：

| 字段 | 需要回答的问题 |
|---|---|
| 读者画像 | 学生处于 L0–L5 哪一阶段？本节第一次接触什么？ |
| 前置知识 | 为完成本节必须会什么？是否已有真实可访问的补修课？ |
| 一个核心问题 | 学生学完这节，最关键的一个问题应当会解决什么？ |
| 2–4 项可观察目标 | 能“解释 / 计算 / 实现 / 分析 / 判断”什么具体任务？避免“了解、熟悉、掌握”单独使用 |
| 主例与数据 | 使用哪个现实或合成案例？数字、单位、约定是否足够清楚？ |
| 知识引入顺序 | 已知 → 新问题 → 数字 → 术语/公式 → 练习；识别会发生的知识跳跃 |
| 核心 / 可选界限 | 哪些内容属于基础达标？哪些可延伸、另立一节或暂不讲？ |
| 练习证据 | 每个目标由哪一道独立任务检验？是否仅靠选择题？ |
| 可靠性检查 | 哪些公式、图、代码、引用和数据需要独立核验？ |

**拆课原则**：一节围绕一个主要问题或紧密相关的技能闭环；不为固定页数硬拆，不因“完整”塞入不影响本节达标的高级特例。复杂主题允许分多节。每节也不应只是 3–5 段定义概述。

## 3. 教学写作：固定逻辑，不固定模板标题

推荐的思考顺序：**问题/情境 → 直觉与具体数值 → 概念或算法 → 公式/代码 → 独立练习 → 反馈与总结**。

它是写作逻辑，不是必须逐一出现的栏目名。学生看到的 H2 标题应该根据知识自然命名，而非每篇都出现“场景引入 / 直觉理解 / 符号定义 / 常见误区 / 可选挑战”。

### 3.1 写场景：真实为先，具体优于夸大

- 场景应直接制造本节知识要解决的问题。用学生能想象的数据、行动或现象开头，通常一两个短段就够；不把每一节变成小故事。
- 如使用合成数据，明确标注“为教学构造”，不能伪称实测数据。避免凭空编出“企业采用率”“模型准确率”等统计。
- 能用一个清晰例子说明，不必轮流使用机器人、医生、外卖、银行等无关行业包装同一概念。
- 若本章使用贯穿案例，先复用已有的变量、图例和约定，再引入一个有明确目的的新案例。

### 3.2 讲概念：白话与准确定义成对出现

- 先用日常语言讲出一个可验证的理解，再给正式术语和定义；不要靠类比代替定义。
- 第一次出现的新词，立即解释其具体含义和用途。若是必需的先修知识，可以简短复习并链接真实补修内容；不可给不存在的链接。
- 同一术语在全章保持同一含义。允许换一种说法辅助理解，但应在定义固定后使用。
- 不持续强调“这不是……那不是……”。边界首次必要时讲清，后续在新的误解场景出现时再提醒。

### 3.3 讲公式：先让学生有数字，再让符号帮忙概括

数学公式首次出现时，要做到：

1. 先有具体问题和数值例子；
2. 再展示符号，并解释**所有首次出现的变量、下标、求和范围、单位与维度**；
3. 至少做一次实际代入或逐行计算；
4. 必要时说明为什么这一步合法，而不是从结论直接跳到结论；
5. 涉及假设或适用范围，只讲与当前计算有关系的边界。

例：介绍两个向量相加，先算 `(3, 2) + (-1, 1) = (2, 3)`，解释“东向变化和东向变化相加”，再给一般式。学习 `Σ` 时，从三个具体数的和推到求和记号。学习偏导时，先从一个变量变化带来的损失变化讲起。

正确处理不确定：若有不同符号约定、归一化方式或库行为，要声明本课程采用何种约定；例如本系列可以将 `error = prediction - target` 作为约定，但不能称之为所有教材的唯一规范。

### 3.4 讲代码：正文是教程，不是单元测试日志

- **先呈现最小可运行、准确表达当前算法的主代码**，随后解释关键输入、输出、变量、每一步在数学上对应什么。
- 需要时分段渐进搭建，而不是先贴一个五十行完整脚本，再用一句话介绍它。
- 复杂断言、异常处理、独立求解器、性能基准、边界用例放入“可选代码验证”或下载的完整版本；必要的安全/正确性防护不能随意删。
- 代码示例需说明语言/依赖版本、运行位置、准备数据、预期输出或输出性质；与下载代码保持同源。
- 让学生在运行前**预测**修改某一参数、输入后会发生什么，再运行比较、解释差异。
- 避免使用比本节目标更难的语法来验证基础知识。例如“矩阵乘法入门”不使用复杂嵌套列表推导作为核心讲解。
- 数学可以不要求 Python；只有当代码确实有助于本节目标，才加入代码，并写清可跳过的范围。

### 3.5 讲图：解释抽象关系，图与数字互为证据

- **一图一个教学任务**：说明变化、结构、位置、流程、对比或数据趋势。只有情绪氛围的插画不能充当数学教学图。
- 图中轴、比例、单位、箭头方向、标签、符号、数值必须与正文一致。几何图优先精确 SVG/Canvas/程序绘制并可核对输入数据。
- 图前说明“看什么”，图后指出“从图读出什么”；不重复整段正文。图注不写大段 AI 式口号。
- 手机阅读确保坐标、公式、字母可读；允许专门的移动构图与局部横向滚动，不能牺牲数学比例。
- 图片提供有信息量的 `alt`；不得将图像内的装饰文字当作可索引教材正文。

## 4. 习题设计：学生真的会，而不是会认选项

每一项核心目标必须能映射到一个**核心任务**，任务形式根据动词决定：

| 学习目标 | 优先证据 |
|---|---|
| 解释概念 | 说明理由、区分反例、给出新实例 |
| 计算/推导 | 新数字、完整计算过程、单位/符号核对 |
| 写函数/代码 | 补全函数、修改输入、独立实现短片段 |
| 使用工具/训练模型 | 可执行任务、运行结果与记录 |
| 分析模型 | 比较实验、解释偏差、发现数据泄漏或错误结论 |
| 迁移 | 将已学规则用于陌生但难度可控的情境 |

- 选择题只能辅助检查理解，不能代替所有“会做”的任务。
- 核心题先于进阶题，题目不提前使用下一节才教的新知识。
- 每题提供两级渐进提示、分步参考答案、常见错法和评分/自检依据；至少一题需要学生自行产生过程或答案。
- 提示一优先指向思路而非直接泄露数值；提示二可指向中间步骤。参考解答应说明**为什么**，不是只给最终数字。
- 自动反馈若不含实际判分能力，明确为自查；不能把“浏览完/看过答案”视作知识掌握。
- 练习用的数字最好与正文不同，防止只记住例题结果。

## 5. 内容分层与难度控制

- **核心必学**：学生达成本课 2–4 个目标所必需的知识，正文展开，提供完整推导/练习。
- **可选进阶**：复杂特例、一般化证明、跨场景应用、科研或工程延伸；明确折叠，不能出现在基础达标题或标准前置知识中。
- **可选验证**：完整测试、复杂断言、异常输入、数值对照和工程可靠性检查；保留可重现文件与证据。
- **另立课时**：本身需要新的先修、较长推导或独立练习闭环的知识，不要通过一个长折叠区逃避拆课。

例：向量数乘核心解释 `(3,2)` 在 2、0.5、-1、0 倍数下的分量、长度与方向；反求统一倍率、共线、不同参考原点的绝对位置变换可以作为可选，基础练习不考这些可选内容。

## 6. 自然中文与“去 AI 味”编辑规则

**目标不是让文字假装人写，而是让文字真正为学生的理解服务。** 不以关键词黑名单机械清洗，但需检查以下症状。

### 6.1 高频模式需要人工改写

- 同一篇连续出现“不是……而是……”“不要……”“不能……”“本节不要求……”“后续再讲……”；把必要提醒集中在相关新概念第一次出现的位置。
- 每段都以“这说明”“因此我们可以发现”“值得注意的是”“这正是……的核心意义”收尾，缺少新信息。
- 每一节强行从“在 AI 飞速发展的时代”或虚构故事开头，铺垫长于真正的讲解。
- 大量抽象词替代具体动作：赋能、闭环、底层逻辑、核心竞争力、从 0 到 1、全方位、沉浸式、构建能力、深度理解、真正掌握。
- 不断向读者发号施令：“请注意”“切记”“务必”“千万不要”“接下来我们将”；可用具体的现象/理由/计算取代。
- 句式过分整齐，段段五句、节节十个 H2、每个例子都换一套行业故事。
- 解释重要概念时用模糊话术兜圈，学生读完仍不知“怎么做、怎么算、为什么”。

### 6.2 推荐写法

- 像一位面对学生的老师说话，**自然、准确、克制、具体**。短句与长句随需要变化；不过度口语化，也不模仿社交平台段子。
- 一段回答一个实际疑问；上下段承接具体信息，不靠万能转场句。
- 用可核对的动词和数字代替抽象结论：例如“每个分量都乘 2，所以 (3,2) 变成 (6,4)”比“数乘实现向量变化的统一表达”更易懂。
- 真正需要提醒时明确说“在这组数据上”“只讨论本课定义的二维位移”，避免铺天盖地的免责语气。
- 用少量必要的反例检验理解；不要将同一个边界在引言、图注、误区、练习、总结各完整重复一遍。
- 可适度使用“我们先算”“试着想想”，但无需句句扮演对话者。
- 不凭空引用名人观点、统计或实际公司案例来增加说服力。

### 6.3 同一个知识的改写示例

**不推荐：**

> 向量数乘不是简单的数字运算，而是一种实现向量空间变换的重要工具。需要注意的是，我们不能把负倍数理解为负长度。本节不要求掌握向量模公式，后续还将深入讨论相关概念。通过上述分析，我们可以进一步理解数乘的核心意义。

**推荐：**

> 取向量 u=(3,2)。把它的两个分量都乘 2，得到 (6,4)：向东的变化由 3 变为 6，向北的变化由 2 变为 4。箭头朝向没有变，长度变成两倍。如果乘 −1，得到 (−3,−2)，箭头会反向，长度仍与原来相同。负号改变的是方向，长度本身依然是非负数。

后者不一定更短，但包含可以实际检查的计算。对某些更复杂的知识，必须补充公式推导而非仅靠这一段。

## 7. 不同课程的写法要有差异

| 课程类别 | 首选讲解节奏 | 主要成果/练习 | 避免的问题 |
|---|---|---|---|
| L0 导论 | 典型问题→分类→真实例子→判断 | 识别任务、划定概念范围、选择学习路线 | 一开始堆模型历史与名词 |
| L1 Python | 需求/输入输出→最小代码→逐步修改→独立补全 | 能写、能运行、能解释报错 | 入门与对象引用/复杂测试混讲 |
| L1 数学 | 具体数字/图形→概念→推导→手算→新例 | 能算、能画、能解释符号 | 公式先于数字、图示比例不准 |
| L1 数据处理 | 数据问题→清洗/可视化→比较→报告 | 可复现的数据分析 | 只讲 API 名称不解释结果 |
| L2 机器学习 | 同一问题/数据→模型→损失→优化→评估 | 基线、模型训练、错误分析 | 只展示训练损失或只会 `fit()` |
| L3 深度学习 | 张量形状→计算图→架构→训练/调参→分析 | PyTorch 最小实验、可复现分析 | 模型结构/参数解释跳跃 |
| L4 LLM/CV/多模态/RL | 明确先修→任务与模型机制→可控实验→局限 | 运行的专业实验及解释 | 把随时变化的库/API 用法写成永恒结论 |
| L5 研究与工程 | 问题假设→方案/控制变量→指标→复现→讨论 | 实验报告、数据/算力记录、复现结论 | 将单次结果或小数据集误称研究定论 |

**固定的是知识和练习的质量标准，不是每节课的标题数量、字数、插图或组件种类。**

## 8. 跨课程一致性与知识复用

- 维护统一术语表，尤其是“输入/特征/标签/目标、预测/误差/残差/损失、参数/权重/偏置、训练/验证/测试、收敛/泛化”。注意同词在不同学科的定义与符号约定可能不同；明确上下文。
- 一门系列尽量共享主例、单位、数据来源和符号；需要换新例时交代为什么。
- 上节教过的概念，只短暂提醒并提供回链，不复制长篇定义；新课不直接使用未来才教的术语解释自己。
- 章节末提供回顾和可完成的综合题，组织跨节联系；每个单课的总结不要都写成空泛口号。
- 课程涉及新的库版本、数据集、模型参数、法则，应注明具体环境/文献版本与核验日期；区分稳定原理与会变的工程接口。

## 9. 源资料、版权与事实校验

## 10. 质量验收：先过底线，再看得分

### 10.1 不可发布的阻断问题（任一存在即退回）

1. 数学推导、符号、单位、代码执行或答案存在已确认的实质性错误；
2. 关键前置概念未讲且无可用补修路径，导致本节核心任务无法理解；
3. 核心目标仅靠识别性选择题，缺少真实可操作任务；
4. 核心知识放在隐藏进阶区，基础题却要求它；
5. 数据/图表来源虚构，真实实验、完成率、效果或引用无证据；
6. 素材许可明显不适用或无法核查；
7. 正文严重拼接、重复，或明显缺少完整教学步骤；
8. 兼容修改造成真实教材链接、锚点或阅读记录错误而未处理。

### 10.2 编辑评审量表（建议，不是假定已验证的行业统一标准）

每项 0–4 分：0=缺失/严重问题；1=明显不足；2=基本可用但需修；3=符合规范；4=讲解成熟、有充足证据。合计 28 分。评价需要**逐项给具体例句/题目/图示证据**，不能让 AI 仅凭自我印象打分。

| 维度 | 主要观察点 |
|---|---|
| A. 科学准确性 | 定义、推导、单位、代码和结论范围准确 |
| B. 先修与认知负荷 | 没有跳步；核心与可选分层合理 |
| C. 解释的可理解性 | 从例子到符号有过渡，数值可复核 |
| D. 教学材料匹配 | 图、表、代码与目标相匹配且可靠 |
| E. 练习效度 | 所有目标有独立任务与可信反馈 |
| F. 文章节奏与自然中文 | 避免重复警告、模板痕迹、抽象套话 |
| G. 课程间衔接 | 术语、符号、前后内容与主例连续 |

**建议内部试用门槛**：无阻断问题，七项均≥3。该分数仅为编辑审核参考，不等于学生已经学会，更不意味着可自动正式发布。

### 10.3 必须保留的三类独立证据

- **技术证据**：类型、构建、路由、代码运行、公式解析、图形数值、资源完整性与旧链接兼容；允许自动检查。
- **专业编辑/学科审查**：逐课审阅正文、事实、推导、术语、难度、提示与练习，由具备相应能力的审阅者签署结果；不能由写作 AI 自评代替。
- **目标学生试学**：按前置要求找尚未学过该内容的学习者，在无人补讲的情况下阅读、手算/运行、完成新题；记录卡点、是否使用提示、耗时分布、独立解释是否正确；据此修订。

学时分为预计阅读 / 练习 / 代码实践，编辑估计明确标识；只有样本充分时才能依据试学结果校准。不要以读者速度推测精确时长。

## 11. AI 辅助生产的工作流

**阶段 0：建模** —— 读取课程体系和前后节；写学习者画像、知识依赖、目标、核心/进阶范围与目标—练习矩阵。

**阶段 1：取证** —— 查阅官方教材/文档/论文，记录每个关键事实的出处与许可边界，不复制大段原作。

**阶段 2：先做例题** —— 先确定贯穿数据、手算、预期代码输出和正确图形；验证这些例子，再开始写解释。

**阶段 3：起草** —— 写成自然教学文章，按需要加入公式、表格、图示、代码与练习；标题自然，正文不重复数字编号。

**阶段 4：教学编辑** —— 换成初学者视角逐段提问：“读到这里要知道哪些前提？有没有一个数字能验证？这段是否真的推进理解？”删除模板句和多余提醒，不削弱关键定义与证据。

**阶段 5：技术校验** —— 校验数值、公式、代码、图与下载同源，运行现有工程测试；标注有待复核之处。技术通过后仍只可进入待人工审核的试读状态。

**阶段 6：独立审核和试学** —— 记录编辑决策、审稿者、学生试学证据与修订；审核未完成不得标记正式发布。

批量制作使用“小批量 → 质量核查 → 试学修订 → 扩批”的循环。先使数学、Python、ML 三种样章通过此规范，再向其他课程扩展。

## 13. 发布前最后 12 问

- [ ] 这节有一个具体问题与可观察目标吗？
- [ ] 目标读者可以凭已学知识理解第一段吗？
- [ ] 新概念第一次出现时有解释，重要符号有数值代入吗？
- [ ] 推导步骤是否充分，复杂证明是否恰当地移到进阶区？
- [ ] 图表与示例数值是否能独立算出或核对？
- [ ] 主代码短且完整，运行结果解释是否准确？
- [ ] 基础练习是否真正考查了所有核心目标，而不只是认答案？
- [ ] 提示、解答和自查标准是否让学生能发现自己的错误？
- [ ] 每段是否真正推进理解，是否还存在机械重复的警告和结论句？
- [ ] 正文标题是否自然、无多余编号，文章目录锚点是否可用？
- [ ] 来源与许可、实验环境和版本是否已登记且无虚构？
- [ ] 技术验收、独立审核、学生试学的证据与状态是否分别记录？

---

**最终编辑准则**：如果读者读不懂，先检查我们是否讲得跳跃；如果读者做不出来，先检查是否提供了足够的示例和练习；如果文章显得“AI 味很重”，先检查每个句子是否真正有新信息。让质量来自扎实的教学，而不是文风模仿或篇幅堆砌。
