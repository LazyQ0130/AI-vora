# 发布门禁、版本证据与整改流程

本轮结论仅为准备材料齐备，**没有满足正式发布条件**。24课保持pending-review/preview，整门AI000保持planned；不改manifest或填reviewEvidence。本文件使用现有Schema状态，B/I/O问题类别和人工进展不是新增产品状态。

## Schema实际检查与人工责任

[publicationSchema](https://github.com/LazyQ0130/AI-vora/blob/fc30c72d5572bea05bafd9f9b5b55a54150d634b/src/content/models.ts)要求tech-verified/pending-review/reviewed/pilot/published有technicalEvidence，reviewed/pilot/published另有reviewEvidence；只有published允许public，未校验/下线只能private。Schema只检查字段/组合，不能验证文件里的签署是否真实或学生样本是否充分。

当前没有独立的subjectEvidence、pilotEvidence或时间校准字段，不给Schema发明字段。未来reviewEvidence可以引用一个经维护者核实的证据总目录，里面分别列学科、教学编辑、试学、整改、时间和发布决定；technicalEvidence仍引用适用版本的技术报告。一个非空路径、空白模板或本准备包本身不构成审核证据。

pilot进行中不得冒称已完成试学。全课程发布决策须覆盖全部24课学科与编辑、完整路线的真实衔接和结课能力证据；优先13节单课结果不代表剩余11节已审，也不代表全程完成率。若全程未开展，明确保留该缺口，不能宣布整门正式发布。样本范围和足够性在组织前定义、事后由人核解释，不用一个机械人数/总分替代。

## 每份证据的绑定信息

正式意见、整改、试学与发布决定均需：记录ID、课时稳定ID、内容r、完整教材SHA/内容摘要、日期、实际执行角色、使用方法与范围、原始证据的受控引用、具体发现、处理/保留理由、未决项及签署。公开汇总只披露必要去识别信息，维护者可在受限位置查真实性；不把私人学生原稿推到公开仓库。

教稿提交与本准备文档的提交可以不同：只新增文档不使教材变化，仍审核固定fc30c72。若任何教材、关联数据、图形/公式、题干/提示/答案/rubric或页面行为变化，先比较内容摘要和影响；旧证据只能说明旧稿，不能按相同标题/r号默认继承。

## 问题处理与复核

1. 用[问题登记](ISSUE_REGISTER.md)写精确原文/学生答案/实际运行证据、误解机制、目标与邻课影响。未核实先标待判定；确认阻断时暂停受影响版本和依赖试学，追踪同主例/规则的其他课。
2. 实际负责人提出最小改动与保留理由，维护者单独记录版本决定。只改错字/过期说明、无结构或达标变化可有维持r的依据；核心目标、考核或达标实质改变时升Lesson和Publication版本，保留旧section/exercise锚点、历史报告和旧进度键，新版不继承完成。
3. 技术执行者按改动重验。数学/数据/图改动重新独立推算，代码实际运行，导航或样式变更做必要浏览器检查；仅文档索引不堆无关截图。保留失败和修复记录。
4. 原意见者或有相应能力的复核者核新提交，说明问题是否解决、是否引入新问题。受影响目标用未见新例或新合格学习者再试学；看过旧题/答案的人标复测与暴露，不能装作首次样本。
5. 发布维护者检查剩余B/I/O、证据版本、限制和公开范围，写批准/暂缓/退回理由、文件版本与渠道。签署空白即未决定。发布后按受影响课时、链接/渠道更正并复核实际展示，保留撤回/更新与通知记录。

## 整课状态的额外工程事实

课程级状态当前在[src/lib/curriculum.ts](https://github.com/LazyQ0130/AI-vora/blob/fc30c72d5572bea05bafd9f9b5b55a54150d634b/src/lib/curriculum.ts)适配时设为planned，并非“24个Publication都变published”就自动改变。课程与课时状态必须分别决策；未来若需课程级正式发布，应另做经审核的目录适配方案，保留curriculum V1.0历史事实，不能为展示已发布而直接改原始JSON。此准备轮不实现该变更。
