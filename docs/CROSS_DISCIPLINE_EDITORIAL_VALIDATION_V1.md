## 语言与教学内容的前后对照

### 首次函数：先看得见，再解释名字

原concept先说“def 定义这份步骤，尚未为某个数字计算。double(3) 才会进入函数体执行”，完整代码却隔着binding和defaults才出现。问题不在某个词像AI，而在学生无代码可指认。

改后先给 `value = 3`、`result = value * 2`、`print(result)`，再展示单独函数定义并解释“括号后的冒号表示函数体从下一行开始”“第二行向右缩进四个空格”，最后连接不缩进的调用行。可观察的试学任务是让学生在空白中定义新函数并解释何时执行；本轮仅验证示例和任务可解。

### 共享模板：修正条件，不机械换词

原PY页代码前出现“数学课代码部分需基础 Python 的列表、下标和循环；可先手算，再补修后运行”。这与5.1的先修自查冲突，也把编程课说成可先跳过程序。

改后Python只保留环境、保存与终端命令；该数学说明仍留给确实需要它的数学旧课。修改的是说明适用条件，未把“数学”替换成另一个空泛词，也未借机重写5.2–5.5。

### ML复核：把“未完成”变成下一步动作

原verify说明：“训练损失下降，但还不是 0，参数也尚未等于这两个点的精确直线 w=2、b=1。一次更新不是训练完成。”

改为：“新预测仍分别低于两个目标 0.9 和 1.6，平均平方误差降到 1.685。若继续训练，就从 w=1.3、b=0.8 重新计算下一步梯度；这两个教学点对应的精确直线仍是 w=2、b=1。”

数值和结论边界未变，读者现在有可指出的新参数与下一步操作。是否更容易理解，仍需真实学生解释过程来判断，不以AI自评替代。

## 规范结论与下一步

V1.0表现好的条款包括先做简报、先例题再符号、核心/可选分层、目标对应开放任务、代码与下载同源及三类证据分开。它们使本轮能保留已正确的数学、图和任务，并找到具体缺口，而不靠全文重写。

需要澄清的是熟例自查与独立迁移的区别、首次学编程与应用已学编程的不同讲解重点，以及实际组装内容的学科适配检查。对应的三项V1.1建议均绑定本轮证据；不增加字数、段数、H2数量或素材数量门槛，不把新建议自动升为正式规范。

下一阶段适合少量单课草稿试产，每课仍先简报/取证、再生成、独立校验；不要一次生成整门课或据本轮技术通过扩量正式发布。当前最有价值的下一步是为这三篇安排教师与目标学习者，观察新增任务的真实过程，再决定规范是否定版和是否扩批。
