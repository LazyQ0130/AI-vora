写清希望改善的结果、当前能观察的信息和允许行动，指出一项硬约束。选一次合法的上午转运或等待，按题设核对转运前后、上午借出及归还后的晚间可用量，解释这次选择怎样影响后续；不要求唯一最优安排。

提出至少两项有记录来源、统计范围与去重办法的反馈或评价指标。举一种计分可能遗漏的要求，说明怎样另查或约束。再指出D1/D2目前缺哪些关键数据，给出补采对象和字段，分清假设推演与真实反馈。

给一个不使用强化学习也能执行的基线，可保留或改进现有规则。依据后续影响说明为何可以考虑强化学习，再提出是否值得继续投入的有条件决定：需要哪些记录或模拟条件？怎样在一致条件与未参与调整的情境中比较？写出足以支持继续尝试的具体结果，以及什么情况应先保留简单方案。

提示：先把借车者需要的结果与转运人员能做的动作分开。用同一个站点顺序记数量，再找每次变动的来源；决定方法之前，先问你能拿什么核对它。 / 画三列库存，把一次转运记为一列减、另一列加；再记录本期实际可借数，并按给定去向补回上午归还。给每项指标加上“哪份日志、哪个窗口、怎样只计一次”，最后为基线和候选留同一张比较表。

自查：目标、可观察量和合法行动可执行；至少一项硬约束准确，上午到晚间的数量追踪与借还约定一致。；至少两项指标有日志、窗口、单位和去重方法；指出奖励可能遗漏什么，并安排分项核查或约束。；明确D1/D2缺口与具体补采字段，不把假设算例当实绩；基线规则能按条件执行。；用后续库存影响解释可考虑RL；是否尝试的决定结合数据、模拟、成本与约束，允许合理替代方案。；比较条件一致，包含未参与调整的相关情境和分项结果，明确继续/暂缓的依据，不宣称一次记录或模拟胜出已证明现实可靠。

## project-choice-task / choose-rl-projects

为甲至丁各写一份简短建议：实际交付是什么，题设是否说明当前行动改变后续环境，学习信号或结果对照从哪里来。给出首选解决思路、可执行的简单比较方案及理由，并说明有没有充分理由进一步考虑强化学习。每项指出一个会误导决定的评价结论，不只填学习方式名称。

为丙另写一个能执行的比较安排：先核查模拟的哪些条件，怎样限制行动，在何种相同情境下与基线比较，分别记录哪些结果，哪些情境留到方案确定后检查。说明支持继续研究或保留简单方案的条件，别把“可以构造”直接写成“应该采用”。

解释丁反复修改为何不足以证明模型内部正在强化学习；若有人因此宣称采用了RL，还需什么过程证据？允许合理的规则、规划、预测或生成组合，但要说明改变条件后你的建议会怎样变。

提示：先看各项目验收时要交什么，再找资料怎样支持它。把任务合适与实施条件分开，首选建议应能在当前要求下开始工作。 / 给每份建议留“交付—依据—先做什么—和谁比—结论到哪里”五格；为丙把开发情境与保留情境分栏，先填需要保持相同的条件，再填要从记录核对的结果。

自查：四项均明确交付、题设中的行动后果或其缺失、信号/结果对照来源，有引用具体条件的首选建议。；甲乙丁有能执行的简单方案及比较办法，逐项指出误导评价，不为技术名称强行增加学习任务。；丙区分可构造与值得采用，计划覆盖模拟核验、允许行动、一致条件、分项结果及保留情境，说明继续与暂缓依据。；丁区分改输入、交作品与实际训练过程证据，不据缺证断言从未使用RL；替代或组合方案有条件和理由。
