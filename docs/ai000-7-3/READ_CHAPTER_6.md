# AI000-C06-L01 为什么 AI 会产生不可靠的回答？ r1

先修：已学过生成式AI与LLM、按资料组织回复，能读简单表格和回查来源编号。准备纸笔即可，无需编程、模型账户或真实联网答题。

目标：用具体案例解释语言流畅与事实可靠的区别，说明生成回答与外部事实核查是不同环节，并分析不可靠说法可能来自哪些资料或使用问题；把回答拆成可核查的事实主张，对照原始资料及适用条件区分有支持、与资料矛盾和暂时未知，分别检查来源存在性与引用有效性；修正或独立撰写有依据、可回查且不过度承诺的回答，保留资料缺口，并为未知或冲突设计可执行的后续核查步骤

章节：first-answer 时间、停车、公告都写全了，就能出发吗？ → original-sources 打开原资料，看清每份说明管什么 → split-claims 同一句话，可能需要查好几件事 → check-conditions 常规时段写对了，为什么当天仍去不了？ → evidence-review 把事实判断和引用问题分开记 → why-unreliable 模型怎样写出了流畅却缺依据的话？ → where-errors-enter 缺资料、用错资料和资料冲突，各查哪里？ → checking-workflow 拿到新回答，按什么顺序查？ → revised-answer 给参观者一份可以回查的修正版 → submission-audit-task 换成作品提交，审查整段答复 → venue-answer-task 只有有限资料，自己写一份可靠回答 → takeaways 检查你的每一句确定说法，都能回到哪里

## submission-audit-task / audit-submission-answer

把答复拆成至少五条可分别核查的主张，不遗漏日期、材料、人数、退费和引用。逐条写事实状态（支持、矛盾、未知）、对应原文及适用条件，另列引用是否存在、是否真正支持。遇到事实与引用结论不同，分别解释。说明三份资料怎样共同决定现行要求。

写一份能直接回复咨询者的修正版，为确定信息附正确编号。另列资料缺口，为至少一项未知设计可执行的核查：向谁取得哪份原文、核对哪些条件，确认后怎样更新答复；不编新的政策或网址。

任选两项不同问题，说明它们可能来自缺资料、忽略条件或错误引用中的什么环节。为什么具体日期、正式标题和流畅语气不足以证明答案可靠？若只是让AI再写得专业一些，哪项证据仍没有补上？

提示：先把同一句里能分开成立的说法逐项列出，给每项保留原来的对象、日期和引用编号。暂不因为找到一个正确细节，就接受整段。 / 做两列清单：原文实际改动了哪一项、还有哪些事项未改。再任选一个主张，分别查它的事实依据和括号里的资料编号；把两次检查留在不同格中，其余主张也用同样办法走一遍。

自查：至少五条且覆盖全部关键说法，每条有原文或查过未提供的范围；事实支持、矛盾、未知有具体理由。；正确处理S1一般要求、S2软件例外及S3仅改软件截止；PDF/视频/人数和两类截止均准确。；人数事实由S1支持但原引S2不当，S8清单外与退费未知分别记录；不把真实来源等同有效引用。；完整修正版逐项可回查，没有新增政策；未知有具体核查对象、所需原文、适用条件和更新动作。；解释两种不同可能问题及流畅性边界，明确重写未补足的证据，不把教学回答当模型总体评价。

## venue-answer-task / write-venue-answer

先拆出咨询者要确认的事实。按“问题—对应通知与原文—日期/对象/条件—当前证据状态”做记录。核对活动日期是否周五、所需时段是否完整落在可申请范围、人数与社团条件；逐日列出提前量，不把可以申请写成已经获批。桌椅与投影仪分别查。

独立写一份完整答复，为每项确定信息附V1或V2。指出每项未知及具体补查路径，包括应取得的资料或记录、核对对象与生效范围。写完再逐句反查来源，检查是否新增设备供应、免费承诺、空闲或批准等题设外事实。

解释：若请AI“再详细一点”，为什么不能直接解决本题的资料缺口？假如系统已经检索到V1，仍需要哪些检查才能回答这个具体周五的问题？用本题说明生成表达、找到资料与验证结论之间的区别。

提示：先把咨询里的资格、时段、物品费用和提交要求分成可单独回答的问题。为每项找原文，留空的格不要靠常识填满。 / 在日历上标提交日和活动日，只把两者之间完整经过的日期逐个圈出；再画所需时段与通知允许时段，比较端点。最后把拟答的每个确定句连回一条原文，连不上时记录缺什么证据。

自查：自行拆出全部问题并记录证据状态，按社团/人数/日期/整个时段核对V1与V2，不凭单份通用规则作结论。；列17、18、19三个完整自然日，解释不计16日和20日；区分满足申请规则与管理员实际确认。；完整答复的确定事实都有对应编号和依据，桌椅最多20套免费与投影供应/收费未知分别表达，无新增空闲或批准结果。；每项未知有查供应/收费原文或时段/确认记录的可执行路径，并核对对象、日期和现行范围；自审能发现新增承诺。；用本题解释重写不能补证、检索仍需核对例外与原文；不要求硬造矛盾或宣称模型一定会编造。

# AI000-C06-L02 数据隐私、偏差与公平性 r1

先修：已完成6.1，能按资料核对结论；知道字段、输入、人工核对类别与系统预测的区别，能数条数、读简单分数。无需编程、真实录音、模型接口或法律知识。

目标：根据AI应用的明确任务逐项审查拟收集数据，区分当前必需、条件性需要与不应默认收集的信息，说明收集更多不一定更好；从给定记录发现输入条件的覆盖不足，独立统计不同条件下的处理结果并解释可能影响，区分已观察差异与未经证实的原因；为新应用设计最小必要的数据使用、访问和保存安排，提出覆盖补查、分条件与分步骤核验、人工处理及替代渠道的可执行改进方案

章节：repair-task 报修一盏灯，系统需要知道你的一切吗？ → purpose-first 先说明做什么，再决定收什么 → personal-information 删掉姓名，录音就一定不涉及个人了吗？ → manage-data 收进来以后，谁能看、何时还需要？ → coverage 少收了无关信息，就能处理所有报修吗？ → check-records 逐条比较，哪些类别真的判对了？ → compare-results 6条正确，还藏着怎样的差别？ → fairness 覆盖、偏差和公平性，怎样联系起来？ → improve-service 发现差异以后，下一步具体改哪里？ → event-data-task 换到报名咨询，审查一份收集方案 → library-results-task 换成图书馆查询，自己统计并提出改进 → takeaways 拿着新方案，检查数据与服务是否都说清了

## event-data-task / audit-event-data

先区分通用规则问答与查询本人报名状态。为11项候选数据逐项写用途、当前需要/条件性需要/不应默认收集的判断与理由，明确哪些只在专用流程中使用；至少指出四项不应默认收集的信息。讨论条件时说明怎样仍能完成任务，不能把所有个人字段一律判为永远禁用。

重写一条从提问到答复或转人工的最小数据流程，说明个人状态如何适当核验且不向通用页面开放全体名单。给出至少两种角色的访问范围；再写一项可执行的保存/删除要求，包括复查或处理触发点、负责人及如何核对副本，不能只写“永久匿名保存”或只删界面。

解释为什么“未来可能有用”和“用户自愿上传”不自动让所有数据都必要。指出你的方案保留了哪些功能，什么条件仍须向活动负责人或系统管理者核实；不编法定保存天数或声称已经法律合规。

提示：先为两类请求分别写最终要交回什么，再看每项数据能帮哪一步。只因系统能收、以前存过，并没有说明当前必要性。 / 任选一项候选数据，写“没有它，哪项明确工作会受阻？可用什么更少的信息完成？”；再为数据流画两列：通用页面与专用处理分别拿到什么。管理要求补上何时复查、由谁处理和怎样确认结果，其余字段仍要逐项判断。

自查：11项逐项说明与任务的关系，区分通用问答和本人状态，至少四项不默认收集，条件性数据有明确条件与较少信息替代。；流程能完成规则答复、必要澄清和个人状态接手；核验后只取本人所需状态，不以自报学号或全体名单代替权限判断。；至少两角色的访问范围具体；保存/删除要求包含触发点、负责人、理由复查和副本结果核对，无万能法定天数。；解释未来用途和自愿材料仍须审查，明确保留功能与待核条件；合理不同方案以必要性和可执行性为据。

## library-results-task / compare-library-results

逐条标一致/不一致，列出各组正确与错误的编号。统计甲、乙和全部的总数、正确数、错误数及正确条数/总数，说明每个分母来自哪里。用具体错例解释总体结果为何不足以描述各组，区分已观察的分类错误、可能的咨询影响和仍待确认的原因。

开发者据此说“乙口音的人表达能力差，系统只适合甲”。说明这个结论哪些部分超出了证据；至少提出两项需要补充的数据或比较条件，指出设备、噪声、问题内容同时变化会妨碍什么判断。写出怎样按同一编号分别检查转写和后续分类，不把最终分类统计当作转写正确率。

提出一项具体改进及一种语音失败后仍可完成咨询的替代方式。说明补查所需的最小条件标签/资料、访问和保留安排，避免为公平性无限收集身份。最后安排改进后的新独立检查：覆盖什么、与谁在什么相同条件下比、分别记录什么，不只在这10条上反复调到全对。

提示：先不看开发者的结论，按每行的人工类别和系统类别做比较；再依条件栏分堆，保留编号，避免用行序猜组别。 / 为每组各留总数、正确、错误三格，检查正确加错误能否回到本组总数。再把两组条件一项项并排标出哪些同时变化；沿同一记录编号画原声、核对文字、系统转写、分类输出四格，圈出目前还空着的证据。

自查：逐条结果、各组编号与分母可回查：甲4对1错/5，乙2对3错/5，合计6对4错/10；解释总体掩盖差异且甲也会错。；用具体错例区分已观察结果、可能影响和未知原因，不从小样本或混杂条件判断口音因果、个人能力或普遍歧视。；至少两项补查具体，能分别核对同编号原音/转写与分类实际输入/输出，记录或控制设备、噪声和任务内容。；改进有针对对象，语音失败后仍有文字/主题选择/人工等可完成咨询的路径；条件标签和核查材料有必要性及访问/保留安排。；改进后另留新请求，在一致材料与规则条件下与旧方案比较，记录分组/分步骤及实际可核查影响；不以等量或单一比例代替完整评价。
